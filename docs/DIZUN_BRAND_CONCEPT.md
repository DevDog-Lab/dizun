## 2. 名前の由来 — 「反転」が意味を反転させる

**DIZUN** は、英単語 **`unzip`（解凍）を文字列全体として180度回転させる**という発想から生まれた造語。

小文字の字形を適切にデザインすると、各文字は次のように対応する。

| `unzip` の文字（元の右端から） | 180度回転後 |
| --- | --- |
| `p` | `d` |
| `i` | `i` |
| `z` | `z` |
| `n` | `u` |
| `u` | `n` |

したがって、**`unzip` ↔ `dizun`** という視覚的な関係が成立する。これは単に文字列を逆順に並べることとは異なる。

さらに、**180度回転は「反対方向」「逆の操作」を象徴する**。`unzip`（解凍）を反転させた `dizun` に、反対の操作である `zip`（圧縮）を重ねている。

> **一つの名前に、圧縮と解凍の両方向を込める。**

※実際の見え方はフォント依存。特に `i` の点や字形、`z` の形状は180度回転時に必ずしも一致しないため、ロゴタイプは専用設計・実機検証を前提とする。

## 3. ブランドの約束

**「相手の環境を気にせず、安心して固め、安心して開ける。」**

ファイルを圧縮する側も、解凍する側も、意識すべきことを最小限にする。特に日本語を含むファイル名や、macOSとWindowsの間で受け渡すアーカイブを重視する。

ただし、すべての形式・すべての破損ファイルで完全な互換性を保証する、という意味ではない。対応範囲と制限は製品仕様と検証結果に基づいて明示する。

## 4. 価値提案と優先順位

1. **文字化けへの強さ**：日本語ファイル名、文字コードの違い、Unicode正規化の違いを適切に扱う。アーカイブ内のファイル内容自体の文字コード問題は、ファイル名の問題と区別して仕様化する。
2. **OS間の互換性**：macOSで作ったアーカイブをWindowsで扱う場合、またその逆のケースを重点検証する。
3. **圧縮と解凍の一体感**：どちらの操作も同じくらい自然に扱えるUI/UXを目指す。
4. **Finderとの親和性**：macOSらしい操作感とFinder連携を重視する。Finder上での表示・操作方法は技術的な実現性に基づき要件定義で確定する。
5. **透明性と信頼性**：オープンソースとして仕様、既知の制約、修正状況を追跡できるようにする。

## 5. 想定利用者

- ファイルの取り扱いにおける信頼性と透明性を重視する人

## 7. ビジュアルアイデンティティの方向性（提案）

### ロゴタイプ

- 表示名は **DIZUN**、デザイン上は小文字 **`dizun`** の使用も検討する。
- **`dizun` を180度回転させると `unzip` に読める**視覚的仕掛けをロゴの核にする。
- 回転による可読性を優先し、既存フォントで成立しなければカスタム字形を制作する。
- 通常表示、180度回転表示、縮小時、ダークモードで視認性を検証する。

### アプリアイコン

- 圧縮／解凍の**双方向性や反転**を示唆する。
- ファイルやアーカイブの道具であることが、小さいサイズでも分かることを優先する。
- 汎用的なZIPアイコンの模倣を避け、独自のシンボルを検討する。

### 動き

- 180度の回転は、オンボーディングやWebサイトで名前の由来を伝える短いアニメーションに活用できる。
- 基本操作では動きに依存せず、アクセシビリティ設定（視差・動きの軽減）を尊重する。
