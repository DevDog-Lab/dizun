# 画像最適化機能の検討（ImageOptim相当）

作成日: 2026-11-19。ユーザー要件: 「画像ファイルをドラッグしたら圧縮されるようにしたい」（https://github.com/ImageOptim/ImageOptim 相当）。
状態: **提案**（実装承認待ち）。

## 1. ImageOptimの実態（調査結果）

- **ライセンス: GPL-2.0**。本体はZopfli/PNGOUT/OxiPNG/PNGCrush/JPEGOptim/Jpegtran/Guetzli/Gifsicle/SVGO等の**外部最適化ツール群のGUIフロントエンド**。
- 各ツールのライセンスは混在（zopfli=Apache-2.0、oxipng=MIT、pngquant/gifsicle/jpegoptim=GPL、PNGOUT=再配布制約あり）。
- **DIZUNへの制約**: GPLコードはMITのDIZUNに複製できない（思想・仕組みの参考は可、コード copying は不可）。GPLツールの同梱も配布義務が発生するため本プロジェクトの方針に合わない。
- 現在の開発機に外部最適化ツールは導入されていない（要確認済み: optipng/pngquant/oxipng/zopfli/jpegoptim/gifsicle すべて無し）。

## 2. 提案: フェーズ1 — 外部依存ゼロの自前最適化（Appleフレームワーク＋既存deflateコーデック）

### 対象と処理

| 形式 | 処理（すべてロスレス） | 期待効果 |
| --- | --- | --- |
| PNG | 付随チャンク削除（テキスト/EXIF。sRGB・ICCP・pHYsは保持）+ **IDATをzlib最大レベルで再圧縮**（生データは一切変わらない） | 未最適化PNGで大きく。実測: sips生成PNGが **57.6%減**（44,714→25,768バイト。ancillary 1,552バイト+IDAT 43,033→25,639） |
| JPEG | APP セグメント（EXIF等）の削除（orientation=回転情報とICCは保持オプション）。**画素はビット完全一致** | メタ付き写真で数十KB〜。GPS位置情報も消える=プライバシー上の副次効果 |
| GIF/HEIC/WebP | フェーズ1では対象外（GIFのLZW再最適化はgifsicle依存、HEIC/WebPは再エンコード=非可逆のため） | — |

### 安全設計（DIZUNの原則に準拠）

- **元ファイルは絶対に壊さない**: 一時ファイルに書き→再デコード検証（PNGはIDAT解凍結果が元とバイト一致、JPEGは画素非接触を構造上保証）→**小さくなった時だけ**アトミック置換
- 大きくなる/変わらないファイルはそのまま触らない
- 上書き方式の選択肢（ユーザー決定事項）: (a) ImageOptim同様にその場置換 (b) 元をゴミ箱に残す

### UX（既存機能との切り分け）

- Dock/ドロップレットに**画像ファイルのみ**がドロップされた場合 → 最適化（それ以外は従来どおりZIP化）
- Finderサービス「DIZUNで画像を最適化」（`public.image`）を追加
- フォルダのドロップは従来どおりZIP化（フォルダ内部の無断一括書き換えを避ける。フォルダ内一括最適化はフェーズ2）
- 結果表示: 「N枚・合計 X MB → Y MB（Z% 減）」

## 3. フェーズ2（将来・任意）: 外部ツール統合

- 許容ライセンスのツールのみ同梱検討（oxipng=MIT、zopfli=Apache-2.0）。GPL（pngquant/gifsicle）は同梱しない
- または「Homebrew導入済みなら検出して利用」（同梱なし・導入済み環境のみ高速化）
- SHA固定・監査・THIRD_PARTY_NOTICES更新が前提（PUBLICATION_POLICY準拠）

## 4. 工数と優先度の評価

- フェーズ1: エンジン（PNG chunk解析・zlib再圧縮・JPEG セグメント解析）+ UI統合で実装〜検証まで1作業回。**外部依存ゼロ・MITクリーン**なのでブランド方針（依存ゼロ）と整合
- フェーズ2: ツール調達・ビルド・監査が主体。効果は追加だが運用コスト大。ImageOptim級の極限圧縮を狙うなら必要
- 推奨: **フェーズ1のみ先行**。効果の実測（57.6%減）は十分説得的で、リスクが最小

## 5. 決定が必要な事項

1. フェーズ1の実装着手の可否
2. 上書き方式: その場置換 / 元をゴミ箱に残す（既定推奨: その場置換+小さくなった時だけ）
3. JPEG の EXIF 削除の既定（推奨: 削除。ただしorientation/ICC保持。ユーザー設定で残す選択可）
